# خطة مراجعة الآيات على أجزاء

`src/data/verseMemoryPlan.json` بيانات تعليمية للنسخة الحالية: قراءة عاصم برواية حفص بالرسم العثماني. لا تحتوي نص الآيات. كل سجل يضم المرجع، وعدد الكلمات المفصولة بمسافة، ومستوىً تقديريًا، وبصمة النص، وحدود الأجزاء **بعد** أرقام الكلمات. مثلًا `[5, 10]` يعني الكلمات 1–5 ثم 6–10.

التقدير الأولي: سهل حتى 10 كلمات، متوسط من 11 إلى 24، صعب من 25 فما فوق. يبدأ المتوسط بجزأين، والصعب بثلاثة أو أكثر. يوازن المولد الأحجام ويُفضّل علامات الوقف القريبة، لكنه لا يفهم المعنى فهمًا تفسيريًا؛ لذلك تُراجع الفواصل قبل اعتمادها بحثيًا. `difficultySource` و`chunkSource` يميزان الاقتراح عن التحرير اليدوي. لا تعيد أوامر `dev` و`build` توليد الملف فوق تحرير المساهمين.

بعد تعديل النص القرآني نفسه، تفشل بصمة الآية في فحص البناء. يجب مراجعة الآية وتحديث سجلها صراحةً من الباني المحلي أو ورشة المساهمين، ثم فحص الحدود الجديدة. لا تُغيّر نص القرآن لإصلاح فاصل غير مناسب. `npm run prepare:memory-plan` يفحص السجلات الـ6,236 وينسخ الملف المعتمد إلى `public/verseMemoryPlan.json` للاستخدام الكسول في المراجعة. `npm run test:memory-plan` يفحص تغطية الكلمات والترتيب والبصمات وورشة المساهمين.

في وضع المراجعة لا تغيّر دورات الأجزاء المؤقتة مرحلة السورة أو المؤقت المتبقي أو الحلقة أو النقاط. يُسجَّل عدد الدورات والأجزاء التي صرّح المتعلم بصعوبتها محليًا في `quran_chunk_practice_v1`، ويُحذف مع تصفير بياناته. إذا غاب سجل أو خالفت بصمته النص، تستمر المراجعة المعتادة بلا تصنيف أو تدريب أجزاء لتلك الآية.
